# uni-app 专项规范

## 目标

统一 uni-app 项目的跨端边界、平台差异、条件编译、插件管理、权限声明、样式适配和多端测试要求，避免某一端修复破坏另一端。

## 适用范围

适用于使用 uni-app 开发的 H5、小程序、Android、iOS 和其他目标平台应用，以及被 uni-app 消费的共享 TypeScript 逻辑和组件。

## 规范要求

- 项目必须记录支持平台、运行环境、构建命令、发布目标和验收范围。
- 平台差异必须优先封装在 adapter、service 或 composable 中，不得在多个页面复制 `#ifdef` 和平台字符串。
- 条件编译块必须保持最小范围，只包住确实存在平台差异的代码，不得包裹整段无关业务逻辑。
- 使用相机、定位、分享、支付、文件、蓝牙、消息推送、扫码和登录等端侧能力前，必须声明支持平台、权限前置条件和失败降级。
- 原生插件必须记录名称、版本、权限、支持平台、构建影响和发布影响。
- 公共页面组件、跨端组件、组合式函数、平台 adapter 和插件封装必须提供 TSDoc、JSDoc、组件文档或等价契约说明，并遵守通用注释规则。
- `pages.json`、路由路径、页面标题和导航样式变更必须同时说明影响平台。
- 跨端样式必须使用 uni-app 支持的单位、选择器和安全区处理方式。
- 静态资源必须考虑各端包体、路径、缓存和格式限制。
- 每个跨端能力变更必须附带验证说明，至少覆盖受影响目标端。

## 平台差异与权限

H5、小程序和 App 的生命周期差异必须在页面或 composable 边界处理，不得假设所有端都有同一事件顺序。

权限申请必须与业务场景对应。权限文案、拒绝授权、取消授权、弱网、超时和降级策略必须在目标平台验证。

支付、定位、消息推送、文件上传、扫码和登录属于高风险能力。声明支持的平台必须完成对应平台验证，不得只在 H5 验证后声明支持小程序和 App。

## 多端测试

多端回归必须覆盖导航、存储、权限、登录、支付、关键表单、网络失败、页面返回、横竖屏和安全区。无法覆盖的平台必须在评审中说明风险、原因和替代验证方式。

条件编译、平台 API、原生插件和包体变化必须纳入发布检查。平台专属资源应当分平台放置或懒加载。

## 跨端文档注释

跨端组件、平台 adapter、插件封装和组合式函数必须说明支持平台、权限前置条件、失败降级、返回值差异和验证范围。条件编译分支存在平台差异时，必须通过注释或相邻文档说明差异原因。

```typescript
/**
 * 调起目标平台的扫码能力
 *
 * @returns 扫码结果
 * @throws 用户拒绝授权或平台不支持扫码时抛出业务错误
 */
export function scanCode(): Promise<ScanResult>
```

## 常见反模式

- 只在 H5 验证功能，却声明支持小程序和 App。
- 原生插件没有版本、权限和发布影响说明。
- 条件编译散落在页面中，无法判断平台差异。
- 依赖某个平台的兼容行为，导致其他端异常。
- 权限失败、取消授权和弱网场景没有处理。
- 跨端组件和 adapter 缺少平台差异说明。

## 检查清单

- 支持平台、发布目标和验收范围是否明确？
- 平台特定代码是否隔离并记录差异？
- 原生插件是否记录版本、权限、平台和发布影响？
- 导航、存储、权限、登录、支付是否在目标平台验证？
- 条件编译是否最小化且可追踪？
- 跨端组件、adapter 和插件封装是否说明平台差异与失败降级？
- 多端回归是否覆盖关键流程和高风险能力？
