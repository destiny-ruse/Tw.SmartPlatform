# Vue 专项规范

## 目标

统一 Vue 项目的组件边界、命名、状态管理、路由拆分、接口调用、样式、可访问性、兼容性和前端工程质量要求，使 Web 应用、管理后台和组件库保持可维护、可测试、可演进。

## 适用范围

适用于基于 Vue 的 Web 应用、管理后台、组件库、前端业务模块和 Vue TypeScript 项目。

## 规范要求

- 项目必须记录 Node.js 版本、包管理器、构建命令、测试命令、浏览器兼容范围和发布产物。
- Vue 组件文件和组件名必须使用 PascalCase，并优先使用名词或名词短语。
- 组合式函数必须使用 `use` + Pascal 语义的 camelCase，并表达封装的状态或行为。
- 页面组件必须负责路由级编排，领域计算、请求转换和复用交互必须下沉到 feature、composable 或 service。
- 组件 props、emits 和插槽契约必须明确；使用 TypeScript 的项目必须用类型表达公开契约。
- 公共组件、组合式函数、插件和导出工具必须提供 TSDoc、JSDoc、组件文档或等价契约说明，并遵守通用注释规则。
- API 调用必须集中到 service、client 或 adapter 模块中，不得散落在大量组件内。
- 状态管理必须清晰表达数据来源、更新路径和副作用，不得依赖隐藏的跨组件状态修改。
- 路由记录必须具备稳定名称、路径参数约束和必要 meta 字段，不得在页面内散落硬编码路由字符串。
- 大型应用必须使用路由级代码拆分和必要的资源懒加载。
- 用户可见文案必须纳入国际化；表单 label、placeholder、错误提示和 ARIA 名称必须分别处理。

## 组件与模块边界

组件必须区分页面组件、业务组件和基础 UI 组件。页面组件负责路由和布局编排；业务组件承载业务交互；基础 UI 组件保持通用，不得依赖具体业务服务。

功能模块应当通过公开出口暴露组件、类型和服务。不得从其他模块导入 `internal`、私有目录或页面文件。组件不得直接修改 props、全局对象或其他模块内部状态。

单文件组件必须保持模板、脚本和样式职责清晰；当文件承担多个业务流程时，必须拆分组件或 composable。

公共组件必须说明 props、emits、插槽、暴露方法、可访问性名称、错误状态和副作用。组合式函数必须说明输入参数、返回状态、异步行为、取消方式、错误语义和依赖服务。

```typescript
/**
 * 管理订单详情查询状态
 *
 * @param orderId 订单标识
 * @returns 订单详情、加载状态和刷新方法
 */
export function useOrderDetail(orderId: Ref<string>)
```

## 样式、兼容性与可访问性

颜色、字号、间距、层级、圆角和阴影等可复用值必须来自设计变量或项目样式 token，不得在多个页面重复硬编码。

可访问性必须纳入组件设计和评审。交互控件必须具备键盘访问、可见焦点、可读名称和明确状态提示。不得用无语义 `div` 模拟可点击按钮。

使用新的浏览器 API、CSS 特性或设备能力前，必须确认目标浏览器、WebView 和设备支持范围。网络失败、超时、离线、接口字段缺失和资源加载失败必须有可感知降级，不得让页面永久空白或卡在 loading。

## 常见反模式

- 一个组件同时处理页面布局、业务规则、接口调用和复杂状态。
- API 调用散落在多个组件中，错误处理不一致。
- props 和 emits 没有契约，组件调用方只能阅读实现。
- 公共组件和组合式函数缺少契约说明。
- 全局状态被多个组件随意修改。
- 大应用未做路由级拆分，首屏加载过重。
- 可访问性名称、焦点和错误状态缺失。

## 检查清单

- Node.js 版本、包管理器、构建命令和兼容范围是否记录？
- 组件边界是否匹配业务概念或复用场景？
- API 调用是否集中在服务模块？
- props、emits、插槽和路由契约是否明确？
- 公共组件和组合式函数是否具备 TSDoc、JSDoc 或等价契约说明？
- 状态更新路径是否可追踪？
- 样式 token、可访问性和兼容性是否纳入评审？
- 大型页面是否使用路由级代码拆分？
