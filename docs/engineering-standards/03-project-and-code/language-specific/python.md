# Python 专项规范

## 目标

统一 Python 项目的环境隔离、依赖锁定、命名、注释、类型标注、目录组织、导入行为和运行稳定性要求，避免动态语言特性导致可维护性和交付可重复性下降。

## 适用范围

适用于 Python Web 服务、脚本工具、数据处理任务、自动化任务、SDK、内部平台工具和可提交到仓库的 notebook 辅助材料。

## 规范要求

- 项目必须使用虚拟环境或等价隔离机制。
- 项目必须提交可重复安装的依赖描述；关键项目必须使用锁定文件。
- 项目必须记录 Python 版本、依赖安装命令、测试命令、启动方式和运行入口。
- 包、模块、函数、方法、变量和参数必须使用 snake_case。
- 类和异常必须使用 PascalCase；异常类应当以 `Error` 结尾或使用项目内稳定异常命名。
- 常量必须使用 UPPER_SNAKE_CASE，并只表示真正稳定的不可变值。
- 布尔变量和函数应当使用 `is_`、`has_`、`can_`、`should_` 等判断语义。
- 公共函数、复杂领域逻辑、跨模块接口和数据结构必须添加类型标注。
- 公共模块、类、函数、异常和跨模块接口必须提供 docstring 或等价契约说明，并遵守通用注释规则。
- 模块导入必须轻量、可预测，不得在 import 阶段执行数据库连接、HTTP 请求、消息订阅、文件写入或任务启动。
- 项目必须使用统一格式化、Lint、类型检查和自动化测试。

## 目录与运行入口

应用代码、测试、脚本、迁移和 notebook 必须分离。notebook 可以用于探索、分析和说明，但不得成为生产业务逻辑的唯一载体。

CLI、Web 服务、批处理任务和定时任务必须具备清晰入口。入口必须显式加载配置、建立外部连接、初始化日志和启动任务，不得依赖模块导入副作用。

外部协议字段和生成代码名称必须隔离在边界层；进入领域模型后应当转换为 Python 命名风格。

## 类型、异常与日志

类型标注必须服务于可维护性。对外接口、核心模型、复杂数据结构和测试 fixture 必须优先标注。不得使用过宽的 `Any` 掩盖真实边界。

异常必须保留上下文，不得捕获所有异常后静默跳过。服务、任务和脚本必须输出结构化日志，记录任务标识、输入边界、影响范围、失败原因和关联标识。

数据处理任务必须具备幂等性、批次边界、进度记录和可恢复策略。涉及生产数据时，必须先在受控环境验证。

## docstring 文档注释

公共模块、类、函数、异常和跨模块接口必须使用 docstring 说明职责和调用契约。项目内必须统一 docstring 风格，不得在同一项目内混用多套格式。

函数 docstring 必须按适用场景说明参数、返回值、异常、外部依赖、副作用、幂等性和性能边界。类型标注不能替代契约说明。

```python
def scan(package_name: str) -> list[type]:
    """扫描指定包路径下的服务类型

    Args:
        package_name: 要扫描的包名

    Returns:
        发现的服务类型集合

    Raises:
        ValueError: package_name 为空时抛出
    """
```

## 常见反模式

- 全局安装依赖，项目无法在新机器上重复运行。
- 依赖文件未锁定，构建结果随时间变化。
- 导入模块时执行数据库连接、HTTP 请求或任务启动。
- 生产逻辑只存在于 notebook 中。
- 捕获所有异常后静默跳过。
- 使用 `Any` 和字典传递核心业务对象，导致字段缺失在运行期暴露。
- 公共函数缺少 docstring，调用方只能阅读实现。

## 检查清单

- Python 版本和虚拟环境创建方式是否记录？
- 依赖是否可重复安装，关键项目是否具备锁定文件？
- 应用代码、测试、脚本和 notebook 是否分离？
- 是否避免 import-time side effects？
- 命名、类型标注和异常语义是否符合要求？
- 公共接口是否具备 docstring 并覆盖参数、返回值和异常语义？
- 服务、任务和脚本是否使用结构化日志？
- 数据处理任务是否具备幂等、批次和恢复边界？
