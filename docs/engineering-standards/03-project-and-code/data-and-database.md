# 数据与数据库规范

## 目标

统一数据格式、数据库命名、审计字段、数据库迁移、数据回填和数据修复要求，降低数据不一致、不可回滚发布、跨租户访问、线上阻塞和敏感数据泄露风险。

## 适用范围

适用于关系型数据库、由迁移工具管理的 Schema 变更、索引变更、约束变更、数据回填、数据修复脚本、接口数据格式、消息数据格式、导入导出文件和跨系统数据交换。

## 规范要求

- 数据格式必须在接口、消息、数据库和文档中保持一致。
- 日期时间、金额、枚举、ID、布尔值、分页游标和可选字段必须使用稳定、可验证、跨平台一致的表达。
- 数据库对象命名必须表达业务含义，表、字段、索引、约束和迁移文件必须可读、可查、可追踪。
- 关键业务表必须具备审计字段，至少能够追踪创建时间、更新时间、创建人、更新人和逻辑删除状态。
- 多租户表必须具备租户边界字段，所有常规查询必须带租户条件。
- 每个数据库迁移必须有唯一、可排序、可追溯的名称，并说明业务意图。
- 已进入共享环境的历史迁移文件不得修改；需要修正时必须创建新的迁移。
- Schema 变更必须优先采用向前兼容步骤，并明确应用发布顺序。
- 数据回填和数据修复必须可分批、可重入、可观测，并限制单批影响范围。
- 生产数据修复脚本必须经过测试环境验证，不得直接在生产环境执行未验证脚本。

## 数据格式

公开契约中的日期时间必须包含明确时区语义。金额不得使用浮点数表达，必须声明币种、单位、精度和舍入规则。枚举值必须稳定且可扩展，不得改写已有枚举值含义。ID、游标和 Token 必须作为不透明字符串处理，不得要求客户端解析内部结构。

缺省、空集合、字段省略和显式错误必须在契约中说明。系统之间传输的数据不得直接依赖数据库字段名；领域模型、接口模型和存储模型应当保持边界。

## 数据库命名

表名、字段名、索引名和约束名必须清晰表达业务含义。名称不得使用个人缩写、临时编号或含义不明的简写。

索引和约束名称应当能识别所属表、字段和用途。迁移文件名必须包含序号、日期或工具约定前缀，以及可理解的业务摘要。

数据库对象命名应当保持一致风格。遗留对象命名不一致时，新代码应当通过映射或适配隔离，不得把遗留命名扩散到新的接口和领域模型。

## 审计字段

业务表应当具备创建、更新、删除和操作者追踪能力。常见字段包括：

- `created_at`：记录创建时间。
- `updated_at`：最后业务变更时间。
- `created_by`：创建主体标识。
- `updated_by`：最后更新主体标识。
- `deleted_at`：逻辑删除时间。
- `deleted_by`：逻辑删除主体标识。
- `tenant_id`：租户或组织边界标识。

审计字段必须由应用层或数据库层可靠写入，不得依赖人工补录。审计时间字段必须使用统一时区语义和可排序类型。审计字段不得存储个人敏感信息明文；需要人员信息时，应当保存稳定主体 ID。

软删除数据默认不得出现在业务读取、唯一性校验和列表查询中；需要读取已删除数据时，代码或查询必须显式表达。

## 数据库迁移

数据库迁移必须与应用发布顺序匹配。涉及旧版本应用兼容时，迁移不得导致旧版本代码无法读取当前 Schema。

Schema 变更应当采用向前兼容方式，例如先新增可空列或新表，再发布读写兼容代码，最后清理旧结构。新增约束或唯一索引前必须验证历史数据质量，并在迁移说明中记录清理方式或例外风险。

每个迁移必须提供回滚策略。无法完全自动回滚时，必须说明数据保全、人工恢复步骤和停止条件。删除表、删除列、收紧约束、批量重写数据、重建大索引等破坏性变更必须在评审中明确影响范围、验证方式和恢复步骤。

## 数据回填与修复

数据回填和修复脚本必须具备执行边界、幂等条件、日志记录、进度指标、失败处理和停止条件。不得在单个事务中无界扫描或锁定大表。

数据回填必须维护租户边界、审计字段和软删除语义，不得绕过应用约束造成跨租户写入。生产数据修复必须记录影响范围、执行人、验证方式和回退处理。涉及个人信息或敏感数据时，必须遵守安全规范。

## 落地要求

- 涉及数据库结构、索引、约束或数据回填的变更必须在代码评审中说明迁移顺序和回滚方式。
- 发布计划必须识别数据库变更对旧版本应用、报表、接口和下游系统的影响。
- 关键迁移必须提供执行监控方式，例如进度、耗时、失败数量和影响行数。
- 数据修复脚本必须在测试环境验证执行结果，并保留验证证据。

## 检查清单

- 数据格式是否在接口、消息、数据库和文档中保持一致？
- 数据库对象命名是否表达业务含义？
- 关键业务表是否具备审计字段、租户边界和软删除语义？
- 迁移文件是否唯一、可排序、可追溯？
- Schema 变更是否采用向前兼容步骤？
- 回滚策略是否覆盖 Schema、数据和应用版本？
- 数据回填是否可分批、可重入、可观测并限制影响范围？
- 生产数据修复是否经过测试环境验证并记录执行边界？
